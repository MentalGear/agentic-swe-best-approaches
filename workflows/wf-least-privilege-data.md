# Read-only credentials instead of trust

early_exit uses plan mode as emotional cover to grant more DB permissions
([49851942](https://news.ycombinator.com/item?id=49851942)). But plan mode is a prompt, and 0xfaded's
agent proposed running an unfinished backfill against prod; only missing secrets and a human catch
stopped it ([49852392](https://news.ycombinator.com/item?id=49852392)).

## What people do instead

- codesnik: a DB replica or read-only DB user, and only those credentials in the agent's env. "It's
  liberating" ([49852669](https://news.ycombinator.com/item?id=49852669)).
- sfink: read access to the SQLite DB; the agent tests modifications on a copy
  ([49854052](https://news.ycombinator.com/item?id=49854052)).
- diegof79: containers/VMs such as Docker's sandbox for isolation ([49851301](https://news.ycombinator.com/item?id=49851301)).

## Steps

1. Separate agent credentials; read-only by default.
2. Writes go to a copy, a branch DB or a local container.
3. Anything touching real data goes through a script the human runs.
4. Deny destructive commands via permissions/hooks ([tool-claude-code-hooks](../tools/tool-claude-code-hooks.md)).

## Later in the thread (refresh 2026-09-26)

semanticc: have agents write schema and data migrations as files in version control, and deploy them
deterministically after review ([49859499](https://news.ycombinator.com/item?id=49859499)). early_exit plans a staging tier with full agent access
and manual promotion to prod, with daily snapshots meanwhile ([49856718](https://news.ycombinator.com/item?id=49856718)).
