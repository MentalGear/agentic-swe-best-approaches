# Living spec directory and TODO.md

## Two shapes

- **Spec directory** (jeswin): specs are a directory, nested for larger projects, open in your
  editor; the agent updates it as you make decisions; you get grep, diff and git history for free
  ([49852206](https://news.ycombinator.com/item?id=49852206)).
- **Roadmap + epics** (digitaltrees): `/agile/roadmap.md` plus `epic1.md…epicN.md`; one chat session
  per thread; planning sessions may only write inside that folder
  ([49852374](https://news.ycombinator.com/item?id=49852374)).
- **TODO.md as project memory** (spacedcowboy): lists of known bugs and future features, with a rule
  that the file is updated whenever something material changes. "Where are we?" then returns the
  still-open items with task numbers ([49841767](https://news.ycombinator.com/item?id=49841767)).

## Rules that make it work

1. The update obligation lives in `CLAUDE.md`, not in your memory.
2. Specs describe *what and why*; they don't restate code.
3. Keep specs in the repo if agents may edit them; behind MCP or a docs system if only humans may
   (tomasGiden, [49853531](https://news.ycombinator.com/item?id=49853531)).

## Caveat

Specs drift. Pair with [wf-deterministic-views](wf-deterministic-views.md) for anything that can
be generated, and periodically ask a fresh session to diff spec vs code.
