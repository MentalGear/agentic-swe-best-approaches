# Port against an oracle, or have the agent write the converter

The thread's most-cited success was a port. antonmks reports that GitHub Copilot's runtime was ported from
TypeScript to Rust by agents, module by module, at about $120,000 in tokens plus three weeks of a
developer's time, over 135 releases and 14.5 weeks, 430,000 lines becoming 800,000
([49878374](https://news.ycombinator.com/item?id=49878374); numbers as posted, no source linked).
The replies are the useful part.

## What makes a port tractable

- **An oracle.** Shank: porting without changing observable behaviour "is not that difficult with AI"
  when a test suite documents the behaviour "or where the prior application can be used as an oracle".
  With an oracle any system can be matched "with some amount of $ and tokens"; that says little about
  building something new ([49878489](https://news.ycombinator.com/item?id=49878489)).
- **Local reasoning.** wannabe44: file-by-file porting "can be done almost always with local reasoning"
  ([49878468](https://news.ycombinator.com/item?id=49878468)).
- **A converter instead of a translator.** verdverm: when the Go team moved its compiler from C to Go
  "they wrote a program that did ~99% of the work" (talk links in
  [49878932](https://news.ycombinator.com/item?id=49878932)), and suggests prompting "write a program to
  transpile A to B" instead of "port A to B" ([49882021](https://news.ycombinator.com/item?id=49882021)).
  Untried in the thread. OtherShrezzing found $120k for 430,000 lines expensive, since much of it should
  have been boilerplate ([49878568](https://news.ycombinator.com/item?id=49878568)); freeplay replies
  that this would have taken several engineers over a year ([49880408](https://news.ycombinator.com/item?id=49880408)).

## What goes wrong without one

bunderbunder's replatforming kept the tests green and lost observability and scalability; behaviour
nobody had pinned changed ([49879158](https://news.ycombinator.com/item?id=49879158);
[ap-green-tests-drift](../anti-patterns/ap-green-tests-drift.md)). verdverm says Rust developers report
agents reaching for `unsafe` to get around memory-management friction, and subverting tests; they wanted
to know how often it appears in the ported code ([49878908](https://news.ycombinator.com/item?id=49878908)).
Second-hand and unverified.

## Steps

The commenters above didn't describe one combined process; this joins their pieces.

1. Check whether the goal (speed, scale, cost) can be met by incremental changes to the existing system
   before agreeing to a rewrite.
2. Freeze the oracle: the old system running, plus recorded inputs and outputs. Add characterisation
   tests for behaviour nobody wrote a test for, including telemetry and logs.
3. Ask the agent for a converter script first; review it and run it. Use agent sessions for what the
   script can't do.
4. Port module by module, diffing behaviour against the oracle after each step.
5. Have a person read the result for what the oracle can't show: performance shape, observability,
   `unsafe` or equivalent escape hatches.
