# Short sessions passing handoff docs

mikepurvis "got religion" on "many (relatively) short-lived agent sessions passing planning/handoff
docs between themselves". It turns implicit context — "whatever we happened to have talked about" —
into "this is what you need to know, now go", and gives a clean review point and a place for "oh btw
I noticed X" ([49853108](https://news.ycombinator.com/item?id=49853108)).

## Implementations mentioned

- boorang: a Python app reads a phased plan and starts a fresh session per phase, with a standard
  prompt and a handoff check for unforeseen issues. Motivation: "the primacy of the initial part of
  the session context" ([49853767](https://news.ycombinator.com/item?id=49853767)).
- plaguuuuuu: "a few high level slices and having cc work on one per session" beat both
  `/plan` and heavier skill packs ([49853088](https://news.ycombinator.com/item?id=49853088)).
- jfaat: planning skills write docs that later skills read while building, across agents and models
  ([49852673](https://news.ycombinator.com/item?id=49852673)).
- Tracking the phases: beads ([tool-beads](../tools/tool-beads.md)), or several self-promoted trackers
  in [tool-mentioned-unvetted](../tools/tool-mentioned-unvetted.md).

## Handoff doc contents

Goal of this phase · decisions already made (don't revisit) · files in play · done-criteria and how
to verify · open issues found · what the next phase needs. Template:
[templates/handoff.md](../templates/handoff.md).

## Disputed (refresh 2026-09-26)

hoc tried token-saving planning plus phase-execution agents and found "agents actually don't
necessarily communicate better by prose-reduced specs than we do": they had to go back to the planning
agent, with its full context, to fix things. Their conclusion: the executing agent fills gaps, so
either keep the planner holding its hand or expect fixes afterwards ([49855641](https://news.ycombinator.com/item?id=49855641)). saghm asks whether
handoffs are just "manually compacting after every message" ([49857953](https://news.ycombinator.com/item?id=49857953)).

## More reports

- oflannabhra: long sessions got "poisoned" when they asked side questions and the agent fixated on
  them; Fable designed a light git-tracked process with session-hook skills for them after they
  described their frustrations ([49855414](https://news.ycombinator.com/item?id=49855414)).
- Huppie: an orchestrator conversation hands each phase to a fresh, usually cheaper subagent, so
  phases get clean context automatically ([49857325](https://news.ycombinator.com/item?id=49857325)).
- MPSimmons and bushido keep plan docs for multi-session, days-long work, mainly to stop drift from
  the original goal ([49856367](https://news.ycombinator.com/item?id=49856367), [49856982](https://news.ycombinator.com/item?id=49856982)).
- Trackers: bensyverson's `jobs` CLI (author) gives the agent the current task in the context of the
  larger plan via `job orient` ([49859889](https://news.ycombinator.com/item?id=49859889)); see [tool-mentioned-unvetted](../tools/tool-mentioned-unvetted.md).

## Second refresh (2026-09-27)

oflannabhra's git-tracked setup, in more detail ([49860536](https://news.ycombinator.com/item?id=49860536)): the record of done and pending work
lives with the code for when they return months later; tasks that turn out bigger get split inside
the session; git keeps several machines in sync; a separate repo renders views of the work for their
phone; hooks let the agent do the task bookkeeping. They rejected beads and Jira as too heavy.
boorang's head-to-head test favoured session-per-phase over subagents ([49863290](https://news.ycombinator.com/item?id=49863290)).
