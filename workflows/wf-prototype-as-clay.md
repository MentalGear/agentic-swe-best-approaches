# Prototype first, architecture later

Fr0styMatt88's process (tooling work) ([49852784](https://news.ycombinator.com/item?id=49852784)):

1. Quick prototype.
2. Define the language of the app — terms, UI design language — and write it down so you and the
   agent use words consistently ([con-domain-language](../concepts/con-domain-language.md)).
3. Keep prototyping; let the agent write unit tests; lock down behaviour you like and record it.
4. The real architecture comes into focus from real use cases, avoiding premature abstraction.
5. Refactor into it; tests make refactoring cheap.
6. Keep iterating on small pieces. Library swaps, architectural experiments and perf trials that used
   to be expensive are now "throw it there and see what sticks".

> Your code is much more like clay.

## When not to

Large sprawling systems, shared schemas, or anything irreversible — the author says so themself.
See [con-blast-radius](../concepts/con-blast-radius.md).
