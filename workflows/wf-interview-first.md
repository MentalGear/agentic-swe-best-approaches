# Make the agent interview you

## When

You know roughly what you want but not every decision, which the thread agrees is most of the time.
valzam: after adopting a question-asking skill, "a step change in the output quality" and "Claude is
very good at following all the decisions exactly" ([49853409](https://news.ycombinator.com/item?id=49853409)).

## Steps

1. sm-silversight's prompt, verbatim: "don't write any code yet. I want to [describe usage]. Ask me the
   top ten relevant questions to doing this well. We're working up a planning .md we'll handoff to a
   fresh agent." ([49852221](https://news.ycombinator.com/item?id=49852221))
2. Prefer structured, one-at-a-time questions. diegof79 forked the grill-me skill to use Claude Code's
   question tool for a faster UI ([49851420](https://news.ycombinator.com/item?id=49851420)); see
   [tool-ask-user-question](../tools/tool-ask-user-question.md).
3. Capture answers in the plan file or spec, not only in chat.

## Tools

- [tool-grill-me](../tools/tool-grill-me.md): Matt Pocock's `grill-me` / `grill-with-docs` skills.
- [templates/skills/interview/SKILL.md](../templates/skills/interview/SKILL.md): a minimal local version.

## Caveats

- joegibbs: models often ask the *wrong* questions (obvious ones) and silently assume the actually
  ambiguous ones ([49852866](https://news.ycombinator.com/item?id=49852866)). Ask it to rank questions
  by how much a wrong guess would cost, and to list the assumptions it is *not* asking about.
- If there are many questions, your spec is under-specified — which is the point (LeoPanthera,
  [49852255](https://news.ycombinator.com/item?id=49852255)).

## Later in the thread (refresh 2026-09-26)

- istjohn: Opus 5.5 with Matt Pocock's grilling skill is "quite good at surfacing and clarifying
  these issues", and often shows they want a *larger* scope than Claude would assume ([49857123](https://news.ycombinator.com/item?id=49857123)).
- jonmagic gets the most from being interviewed *after* doing some exploration themself, for "the last
  few things it needs before implementation" ([49857763](https://news.ycombinator.com/item?id=49857763)); see
  [wf-plan-as-late-checkpoint](wf-plan-as-late-checkpoint.md).
- Jimmc414: plan mode's value is disambiguation through the question tool, because "the automatic
  disambiguation step is RLHF'd out of the model even when it's needed" ([49856208](https://news.ycombinator.com/item?id=49856208)).
- teliskr writes 10–30 minutes of requirements, then runs superpowers' brainstorming skill to ask the
  gap-filling questions; they don't read the spec it writes and are happy with results ([49856911](https://news.ycombinator.com/item?id=49856911)).
- Counterpoints: samdjstephens and whywhywhywhy found the questions low-value
  ([49856922](https://news.ycombinator.com/item?id=49856922), [49857963](https://news.ycombinator.com/item?id=49857963)); see "Disputed" in [con-underspecification](../concepts/con-underspecification.md).

gosukiwi uses the grilling skill before big features "so you REALLY know what you are building", and
would rather have a brainstorming skill than a built-in plan mode ([49860859](https://news.ycombinator.com/item?id=49860859)).
