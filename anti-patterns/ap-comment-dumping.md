# Comments as the agent's scratchpad

Symptoms (wtallis, meowface, stingraycharles): a config value change gets two new comment lines about
the change; comments record planning discussion; beginner-style restatements of the code; "what" with
no "why" ([49853029](https://news.ycombinator.com/item?id=49853029), [49854105](https://news.ycombinator.com/item?id=49854105),
[49853035](https://news.ycombinator.com/item?id=49853035)).

Fix: a comment policy in `CLAUDE.md` plus [wf-decomment-pass](../workflows/wf-decomment-pass.md).

## Later in the thread (refresh 2026-09-26)

sfjailbird: "9 out of 10 of my revisions to Claude's work is deleting or rewriting comments", despite
detailed instructions ([49856361](https://news.ycombinator.com/item?id=49856361)). matsemann adds comments "about the path not chosen"
([49855100](https://news.ycombinator.com/item?id=49855100); see [ap-anchoring-on-first-choice](ap-anchoring-on-first-choice.md)).

## Disputed

senordevnyc is starting to "let go and stop caring": it's easy to strip en masse, agents can recover
the why from git history and transcripts, and more code is never read by a human
([49857418](https://news.ycombinator.com/item?id=49857418)). hungryhobbit: few people read comments anyway; accurate-but-clumsy is a small price
([49857921](https://news.ycombinator.com/item?id=49857921)).
