# Modes make you answer a meta-question

Article: separate plan and build modes required users "to ask themselves the meta-question of
whether a task deserved planning, and then remember to activate plan mode". That's a decision the
tool could make from context.

Counterpoint: a mode is a cheap, reliable habit. themanmaran: asking for a plan is "a little more
tedious than shift+tab" ([49850790](https://news.ycombinator.com/item?id=49850790)); dgrin91 calls
it "a UX trick, but it works well for my brain" ([49852895](https://news.ycombinator.com/item?id=49852895));
Marha01 thinks a workflow this common deserves a dedicated mode
([49854294](https://news.ycombinator.com/item?id=49854294)).

## Use it

Move the decision into a standing rule so neither you nor a mode switch has to carry it — for
example solarkraft's phrasing rule ("I want to…/Let's…" → plan, "Do X" → act,
[49851108](https://news.ycombinator.com/item?id=49851108)) plus a blast-radius rule. See
[wf-conversational-planning](../workflows/wf-conversational-planning.md).
