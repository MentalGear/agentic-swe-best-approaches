# Never trust a single session

int_19h: "Never trust a single session. Things improve drastically however if you spin up a second
session and ask it to adversarially review everything that the first session produces … This works
even better if you use models from different families" ([49854550](https://news.ycombinator.com/item?id=49854550)).

Reports that back it:

- aaroninsf: two instances of the *same* model regularly correct each other's specs and plans
  ([49852597](https://news.ycombinator.com/item?id=49852597)).
- senderista, jimbobimbo, smnscu review plans written by one vendor's model with another's
  ([49852685](https://news.ycombinator.com/item?id=49852685), [49853092](https://news.ycombinator.com/item?id=49853092), [49852909](https://news.ycombinator.com/item?id=49852909)).
- spike021 validates edge cases with a fresh subagent "without our planning context … without
  preconceptions" ([49853101](https://news.ycombinator.com/item?id=49853101)).
- Bockit: the plan is "a great hook in the process for agentic review" against prior decisions and
  project rules ([49852532](https://news.ycombinator.com/item?id=49852532)).

## Use it

The reviewer must not inherit the author's context; that's the point. Give it the artifact and the
rules, not the conversation. See [wf-adversarial-review](../workflows/wf-adversarial-review.md).

## Disputed (2026-09-27)

rickye26: reviewing a design with multiple agents "has very little marginal value. The review agent
will always find something to improve, but mostly it's just nit and not anything super important"
([49860141](https://news.ycombinator.com/item?id=49860141)).
