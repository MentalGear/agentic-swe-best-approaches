# Never trust a single session

int_19h: "Never trust a single session. Things improve drastically however if you spin up a second
session and ask it to adversarially review everything that the first session produces … This works
even better if you use models from different families" ([49854550](https://news.ycombinator.com/item?id=49854550)).

Reports that back it:

- aaroninsf: two instances of the *same* model regularly correct each other's specs and plans
  ([49852597](https://news.ycombinator.com/item?id=49852597)).
- senderista, jimbobimbo, smnscu review plans written by one vendor's model with another's
  ([49852685](https://news.ycombinator.com/item?id=49852685), [49853092](https://news.ycombinator.com/item?id=49853092), [49852909](https://news.ycombinator.com/item?id=49852909)).
- spike021 validates edge cases with a fresh subagent "without our planning context … without
  preconceptions" ([49853101](https://news.ycombinator.com/item?id=49853101)).
- Bockit: the plan is "a great hook in the process for agentic review" against prior decisions and
  project rules ([49852532](https://news.ycombinator.com/item?id=49852532)).

## Use it

The reviewer must not inherit the author's context; that's the point. Give it the artifact and the
rules, not the conversation. See [wf-adversarial-review](../workflows/wf-adversarial-review.md).

## Disputed (2026-09-27)

rickye26: reviewing a design with multiple agents "has very little marginal value. The review agent
will always find something to improve, but mostly it's just nit and not anything super important"
([49860141](https://news.ycombinator.com/item?id=49860141)).

## Disputed: AI reviewing AI (second thread, 2026-09-28)

- askonomm: "you have AI make code, AI review code ... I hope you can see the stupidity here if you expect to
  see any deterministic results at all" ([49878390](https://news.ycombinator.com/item?id=49878390)). Zardoz84 replies that the reviewer catches errors the
  coding agent made, "However, as you point, isn't deterministic" ([49878540](https://news.ycombinator.com/item?id=49878540)).
- whatever1: the LLM reviewer "will find a nitpick while ignoring the huge fire in the core of the design"
  ([49878762](https://news.ycombinator.com/item?id=49878762)).
- nemo44x uses "an alternate LLM to antagonize the coding LLM" and lets it generate large test suites
  ([49879419](https://news.ycombinator.com/item?id=49879419)); mxey asked who checks the tests ([49878822](https://news.ycombinator.com/item?id=49878822)).
- necovek had Codex with GPT 6 Astra review a one-off benchmarking script that Claude Code (Opus 5.5) wrote;
  it "refactored the shit out of it" without asking about context, and without the same baseline multi-page
  prompt reviewers "go into endless loop of 'improvement'" ([49882809](https://news.ycombinator.com/item?id=49882809)).
- mywittyname: an AI reviewer and a human reviewer both missed queries written against dev databases
  ([49881705](https://news.ycombinator.com/item?id=49881705)).

Consistent with rickye26's earlier dispute above: a second reviewer finds something either way, so its value
depends on the context and stop rule you give it ([ap-endless-review](../anti-patterns/ap-endless-review.md)).
